# 使用选项说明：任务分支 / 增强模式 / 增强深度 / 增强方案

> 适用于 PromptGo v1.2.2 及之后的演示页 · 2026-11-19
>
> 演示页先让你选**任务分支**，再决定面板里出现哪些下拉：
> **模式**决定「用什么口吻和硬要求」，**深度**决定「说得多细」，**方案**决定「出图时对接哪个模型」。

## 0. 任务分支：普通 / 文生图

| 分支 | 面板里出现什么 | 用来做什么 |
| --- | --- | --- |
| 普通（默认） | 增强模式 + 增强深度 | 写文案、写代码、做方案等文字任务 |
| 文生图 | 只有增强方案 | 描述画面，输出可直接粘贴到画图平台的提示词 |

- 分支**只控制显隐与默认值**，不强制任务类型：引擎仍按你的描述判断「是不是出图」。
- 因此普通分支下描述画图也能出图（用默认「通用」方案），页面会提示「识别到出图需求，切到文生图可选平台」。
- 切分支不会清空输入，也不会重置你已选的模式和深度（切回来仍是你上次选的）。
- 出图时模式与深度不生效，所以文生图分支把它们收起，只留方案。
- **分支是组件能力**（v1.3 起）：面板内直接可切，宿主也可以用 `branch` 属性预设、监听 `pe:branch` 同步自己的界面。

## 0.1 三个下拉各自管什么

| 下拉 | 名称 | 管什么 | 会改变 | 不影响 |
| --- | --- | --- | --- | --- |
| 第一个 | 增强模式 | 文风和一条硬要求 | 「约束条件」里追加的那句话（选「精简」还会改段数与是否给成品骨架） | 识别结果、输出长度 |
| 第二个 | 增强深度 | 详细程度 | 段数（4 / 8 / 9 段）与步骤条数 | 文风 |
| 第三个 | 增强方案（悬停提示为「目标平台方言」） | 出图时对接哪个模型 | 图像提示词的尾部参数与负面词写法 | **文本类任务完全不受影响** |

一句话记忆：**选分支定界面，换模式换口吻，换深度换长短，换方案换参数。**

---

## 1. 增强模式（6 种）

模式的作用方式是「往约束条件里加一条硬要求」。除「精简」外，其余五种**段数完全相同**，
差别只在那一句话——所以别指望换模式让结果变长变短，那是深度的事。

| 模式 | 它加的硬要求（原文大意） | 适合的任务 | 不建议用在 |
| --- | --- | --- | --- |
| 结构化 | 输出必须分节，每节用二级标题，禁止大段无结构文字 | 方案、报告、需要粘贴到别处的说明文档 | 想快速对话的场景 |
| 精简 | 删除铺垫与客套，只留信息密度最高的内容，总长不超过需求复杂度的 1/3 | 日常问答、贴进聊天框、连续追问 | 要交付给客户的正式材料 |
| 创意 | 鼓励非常规表达，但必须给 2 个风格差异明显的方案并说明各自风险 | 起名、slogan、创意方向、活动主题 | 需要唯一正确答案的任务 |
| 学术 | 区分事实 / 推断 / 观点，引用须标注来源类型，不得虚构文献 | 文献综述、严谨说明、带引用的分析 | 营销文案（会显得拘谨） |
| 代码 | 以可运行代码为主，解释从简，必须含输入校验与异常路径 | 写函数、脚本、排查报错 | 非技术写作 |
| 智能体 | 按「角色 + 工具 + 循环 + 停止条件」组织，明确失败回退与人工介入点 | 设计 Agent、自动化流程、多步任务编排 | 单轮简单问答 |

同一句需求实测字数（仅换模式）：结构化 1,067 / 精简 646 / 创意 1,078 / 学术 1,082 / 代码 1,065 / 智能体 1,067。
除「精简」外差异极小，印证了「模式不改长度，只改口吻」。

**精简的特殊之处**：它会覆盖深度档位——固定输出 5 段（角色 / 目标 / 任务拆解 / 约束 / 输出格式），
并且不输出「输出骨架」。所以选了精简，再调深度看不到区别。

## 2. 增强深度（轻量 / 标准 / 深度）

| 档位 | 一句话定位 | 段数 | 字数（实测） | 适合谁 |
| --- | --- | --- | --- | --- |
| 轻量 | 先给个能干活的骨架 | 4 | 约 470 | 赶时间、自己会把关 |
| 标准（默认） | 日常默认，规矩写全 | 8 | 约 1,090 | 绝大多数情况 |
| 深度 | 再加风险与反例，可直接交付 | 9 | 约 1,190 | 要交给人、怕跑偏 |

三层递进是固定的：

| 递进 | 轻量 | 标准 | 深度 |
| --- | --- | --- | --- |
| 能不能直接动笔（角色 / 目标 / 步骤 / 格式） | ✅ | ✅ | ✅ |
| 要不要守规矩（背景 + 约束 + 自检 + 追问） | ❌ | ✅ | ✅ |
| 要不要防翻车（风险提示 + 反例） | ❌ | ❌ | ✅ |

判断只需问自己：**你担心 AI 出什么错？**

| 你的情况 | 选哪档 | 原因 |
| --- | --- | --- |
| 只想快点看一眼思路 | 轻量 | 4 段就够动笔 |
| 怕占满上下文 | 轻量 | 约 470 字，标准的三分之一 |
| 有渠道 / 字数 / 语气 / 受众要求 | 标准起 | 这些要求只在「约束条件」段里生效 |
| 不知道需求算不算说清楚 | 标准 | 会生成「待确认信息」，帮你发现漏项 |
| 结果要给领导、客户看 | 深度 | 多一段风险提示 |
| 任务涉及判断（该不该做、有没有坑） | 深度 | 附带反例与失效条件 |

**最容易踩的坑**：轻量档不输出约束段，所以你在原话里说的「发小红书」「语气活泼」「300 字以内」
**不会进正文**。需要它们就至少用标准档。

## 3. 增强方案（出图专用）

只有需求被识别为「做图」时才生效：把同一段画面描述按目标模型的语法补上尾巴。
文本类任务（写文案、写代码、做方案）选哪个方案都不会改变输出。

| 方案 | 输出末尾长什么样（示例） | 适合的平台 | 注意 |
| --- | --- | --- | --- |
| 通用（默认） | `…画面简洁。；避免 低质量、模糊、比例畸变、文字水印、画面杂乱` | 即梦、豆包、可灵等中文平台，或不确定时 | 负面词用中文顿号，平台不认参数 |
| MJ | `…画面简洁。 --ar 16:9 --v 6 --style raw --no 低质量, 模糊, 比例畸变…` | Midjourney v6 | 比例写进 `--ar`；负面词改英文逗号分隔 |
| SDXL | 正文一段 + 空行 + `negative: 低质量, 模糊, 比例畸变…` | Stable Diffusion / SDXL 系 | 负面词独立成行，不混进正文 |
| Flux | `…画面简洁。; avoid 低质量, 模糊…` | Flux 系 | 负面词用自然语言 `avoid` 引导 |
| DALL·E 3 | `…画面简洁。画面中不要出现文字、水印或 logo。` | ChatGPT / DALL·E 3 | 不认参数与负面清单，负面压成一句人话 |

实测同一段描述的长度：通用 188 字、MJ 222 字、SDXL 200 字、Flux 196 字、DALL·E 3 183 字。
差异全部来自尾巴，画面描述本身一个字都不变。

两点细节：

- **负面词分隔符会跟着方案变**：中文顿号在 MJ / Flux / SDXL 里会被当成普通字符吞进正文，所以这三个方案改用英文逗号。
- **比例从哪来**：优先取你原话里的「竖版 / 16:9 / 方图」等说法；没说时按场景给默认
  （营销 16:9、电商 1:1、插画 2:3、头像 1:1、海报 2:3、封面 21:9）。

## 4. 三个下拉怎么组合

先分任务类型，再选具体项：

| 你要做的事 | 模式 | 深度 | 方案 |
| --- | --- | --- | --- |
| 写一段能直接用的文案 | 结构化 | 标准 | 通用（无影响） |
| 贴进聊天框快速追问 | 精简 | 轻量 | 通用 |
| 做给客户看的方案 | 结构化 | 深度 | 通用 |
| 起名 / 想 slogan 方向 | 创意 | 标准 | 通用 |
| 写函数 / 排错 | 代码 | 标准或深度 | 通用 |
| 设计一个自动化 Agent | 智能体 | 深度 | 通用 |
| 出一张图给 MJ | 任意（通常结构化） | 任意（对出图无效） | MJ |
| 出一张图给即梦 | 任意 | 任意 | 通用 |

判断顺序：**是不是出图 → 决定方案；不是出图 → 看文体选模式，再看要不要交付选深度。**

## 5. 常见误解

1. **换模式不会变长**。模式和深度是两个维度，长度只由深度决定（精简模式例外，它自带 5 段上限）。
2. **画图时深度不起作用**。图像分支只有一段可直接粘贴的提示词，三档输出完全一样（实测均为 1 段 188 字）。
3. **精简模式会覆盖深度**。固定 5 段，此时调深度没有效果。
4. **方案只影响出图**。文本任务选 MJ 不会冒出 `--ar`，`--` 参数也永远不会混进正文。
5. **分数不是「回答质量」**。它衡量提示词的信息完备度（清晰度 / 具体性 / 结构性 / 约束完备 / 可验证性），
   轻量档分数天然偏低，不代表结果更差。

## 6. 参数与标签写法

| 选项 | 接口字段 | 组件属性 | 取值 | 默认 |
| --- | --- | --- | --- | --- |
| 任务分支 | —（仅界面） | `branch` | `text` / `image` | `text`（普通） |
| 增强模式 | `mode` | `mode` | `struct` / `concise` / `creative` / `academic` / `code` / `agent` | `struct` |
| 增强深度 | `intensity` | `intensity` | `light` / `standard` / `deep` | `standard` |
| 增强方案 | `platform` | `platform` | `generic` / `mj` / `sdxl` / `flux` / `dalle3` | 服务端配置（默认 `generic`） |

**任务分支没有接口字段**：它只决定面板显示哪些下拉（组件内完成），接口仍是 `mode` / `intensity` / `platform` 三个独立字段。

标签预设：四个属性都支持，改属性即刻生效；面板内手动切换会回写 `branch` 属性并派发 `pe:branch`。

```html
<prompt-enhancer target="#prompt-input" branch="image" platform="mj"></prompt-enhancer>
<prompt-enhancer target="#prompt-input" mode="code" intensity="deep"></prompt-enhancer>
```

取值写错不会报错，会按默认值处理。**标签预设请用规范化取值**（`generic` / `mj` / `sdxl` / `flux` / `dalle3`）；
别名（`sd`、`midjourney`、`dall-e`、`dall·e`）只在接口层归一，写在标签里会回落到 `generic`。

## 1. 判定原则

1. **产出物优先于行业词**：用户要的是图还是文字，先定意图；「营销/产品/媒体」等词只影响领域，不决定意图。
2. **文本产物是否决项**：句子主目的若是文案、脚本、方案、需求、标题、说明，则不判 `image`，即使顺带提到「配图/插图」。
3. **显式反转例外**：出现「只要图 / 不要文字 / 配图即可 / 出图就行」时，文本产物词不再否决。
4. **工具操作不判**：修图、裁剪、转格式、识别图中文字、推荐画风属于操作或咨询，v1 不纳入 `image`。
5. **强标记优先**：`评审/走查/审查` → `review`；`代码/函数/报错` → `coding`，不被视觉名词带偏。

## 2. 判定流程（实现建议）

```
step 1  命中 REVIEW_MARKERS            → review
step 2  命中强编程标记（代码/函数/接口/报错） → coding
step 3  视觉名词 + 生成动作，且未被文本产物否决 → image
step 4  文本产物词命中                  → marketing / product / writing（按词表打分）
step 5  其余按现有 INTENT_KEYWORDS 打分 → _pick
step 6  无命中                          → general
```

**视觉名词**：图、图片、配图、插画、海报、主图、封面、头像、立绘、概念图、分镜图、壁纸、图标、视觉稿、草图、主视觉
**生成动作**：画、绘制、做、生成、设计、出图、渲染、出（纯名词短语可省略动词）
**文本产物否决词**：文案、文稿、文章、脚本、大纲、方案、需求、PRD、标题、解说词、口播、推文、报告、规范、说明、评测

**意图优先级建议**（新增 `image` 的位置）：

```
review > coding > image > translate > summarize > marketing > product > analysis > plan > agent > writing > qa
```

`image` 必须排在 `marketing` 之前：否则「做一张小红书种草的配图」会被营销词抢走；但在 `coding` 之后：「用 Python 画张图表」应保留 coding。

## 9. 待确认问题

1. **图表类**：「画一张流程图/架构图」——v1 归 general 还是 image？建议归 general（更适合文本/代码生成），v2 再评估。
2. **图标与 logo**：算 image 还是 product？本表暂归 image，但商标风险高，需在第 3 阶段加「原创、不复刻品牌」约束。
3. **多图规格**：「九宫格」「三版」是否默认一次输出多段提示词？建议支持 `n` 个变体，阶段 2 定契约。
4. **中文文字**：绘图模型生成中文常乱码，海报场景是否默认「不生成文字、留白由设计工具补」？建议是。
5. **修图/图生图**：确认 v1 明确不支持，并在组件文案中说明。

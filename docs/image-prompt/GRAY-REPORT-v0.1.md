**观察项**（首期重点看，不预设结论）：

1. **平台选择是否符合直觉**：默认 `generic`，用户选了 `mj` 才出参数。若大量复制后手动加 `--ar`，说明默认方言该改。
2. **chips 是否被看懂**：`defaults` 里补的段没在 chips 上标出来，用户可能以为「这些是我说的」。
3. **主体占位触发频率**：`missing_subject` 警告的出现率——高说明壳词剥离后普遍缺主体，需要引导文案。
4. **领域 × 风格 100%（承接率）**：抽样口径下已无不合理样本，词表外只剩 `概念设定`；若反馈里仍出现「风格不对」，
   说明问题不在「词有没有落地」而在「落地的词对不对」——按 `DOMAIN-STYLE-MAP` §4.1 的归因表补别名，别再动禁用表。

## 6. 已知风险

1. **组件体积余量 4.1 KB（9.1%）**：T5 后回到 ≥4 KB，但仍不宽裕；任何 UI 增量都要先核算，或把 chips 改成 `/v1/meta` 懒加载。
2. **反馈日志单文件**：4 MB 滚动一份，长期灰度会丢历史（只剩主文件 + 1 份备份），超过一个月需改按日期分文件。
3. **灰度样本量靠自觉**：内部小范围一周很难凑到 50 票，若样本不足，好评率只能当趋势，不能当验收。
4. **领域 × 风格 100%（承接率，非好看率）**：抽样已无不合理样本；若首期反馈集中在该类，先按 §4.1 归因补别名/拆维度，
   不必暂停放量，也不能对外宣称「图像质量 100% 达标」。

# 报告写法约定（2026-11-19 修订）

正式汇报体，两段话讲完，不列清单。

## 一、三种报告的统一格式

| 报告 | 第一段 | 第二段 | 限制 |
| --- | --- | --- | --- |
| 日报 | 今日工作 | 明日计划 | 每段为一整段话；正文合计 ≤100 字 |
| 周报 | 本周工作 | 下周计划 | 每段为一整段话；正文合计 ≤100 字 |
| 双周报 | 本双周工作 | 下双周计划 | 每段为一整段话；正文合计 ≤100 字 |

- **不分条、不加编号**，每节写成一段连续的书面语。
- **字数口径**：只算两段正文，标点计入，不含标题、日期、版本与页脚说明。
- **结构**：先说结果与数字，再说一两处关键处置，其余留给台账。
- **人称与语气**：陈述为主，不用「我们觉得」「大概」；时间用「今日 / 明日 / 本周 / 下周 / 本双周」。

## 二、用词规范

| 条目 | 规范用法 | 避免 |
| --- | --- | --- |
| 动词 | 完成、达成、发布、修复、验证、推进、压缩至、构建成功 | 顺手修了、跑通、瘦回、搞定、弄好 |
| 数量 | 抽样合理率达 100%、用例增至 318、余量回升至 4 KB | 差不多、够用、挺多 |
| 状态 | 通过、可用、待确认、阻塞 | 应该没问题、大概率行了 |
| 时间 | 今日、明日、本周、下周、本双周 | 今天、明天、这周、接下来 |

禁用词：赋能、闭环、抓手、打法、生态位、强力支撑；也不用感叹号、表情与语气词。

## 三、详细内容去哪

| 内容 | 位置 |
| --- | --- |
| 模块盘点、阶段验收、技术难点 T1–T7、风险 R1–R8、资源需求、口径说明 | [`REPORT-APPENDIX-2026-11.md`](REPORT-APPENDIX-2026-11.md) |
| 验收数据 | [`image-prompt/EVAL-REPORT-v0.1.md`](image-prompt/EVAL-REPORT-v0.1.md)、[`PERF-REPORT-v0.1.md`](image-prompt/PERF-REPORT-v0.1.md) |
| 发布内容与校验值 | [`RELEASE-1.3.0.md`](RELEASE-1.3.0.md) |
| 逐日过程与踩坑 | 各 `DAILY-REPORT-*.md` |

## 四、示例

**日报**

```
## 今日工作
今日完成图像提示词末项优化，抽样合理率达 100%；组件压缩至 40,936 字节，
余量回升至 4 KB 以上；exe 单文件构建成功，并修复演示页样式与启动两项缺陷。

## 明日计划
明日核对 CI 结果，并推进灰度取样。
```

**周报**

```
## 本周工作
本周完成图像提示词阶段验收，抽样合理率达 100%，用例增至 318；
累计发布四个版本至 v1.2.3，三种交付形态均验证可用。

## 下周计划
下周完成灰度首份报告，核实 CI 结果，并启动 1.3 词表扩容。
```

**双周报**

```
## 本双周工作
本双周完成图像提示词从设计到交付，抽样合理率达 100%，盲评 4.27；
累计发布四个版本至 v1.2.3，三种交付形态均验证通过。

## 下双周计划
下双周形成灰度报告，核实 CI 结果，并推进 1.3 词表扩容。
```

## 五、发布前自检

- [ ] 两段齐全，每段为一段话（无编号、无项目符号）
- [ ] 正文 ≤100 字（逐字数过）
- [ ] 通读一遍：无口语词、无禁用词、无感叹号
- [ ] 数字与最新报告一致（用例数以 `tests/run.py --strict` 为准）

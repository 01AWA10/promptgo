# 文生图提示词增强：迭代计划（v1.2 规划）

> 基线：PromptGo v1.1.0（12 意图 / 22 领域 / 55 渠道词条 / 63 语气词条，192 用例全绿，组件 39,778 B / 预算 44 KB）
> 本文件只做规划，不含实现；所有阶段验收通过后才进入下一阶段。

## 1. 迭代目标与范围

### 1.1 目标

把用户的一句「画个夏天海边的咖啡馆」变成**可直接投喂给绘图模型的结构化提示词**：主体、场景、构图、光线、风格、材质、技术参数、负面约束八类信息齐备，并保持现有引擎「离线、零依赖、可解释、可回归」的属性。

量化目标（6 周后）：

| 指标 | 基线（现状） | 目标 |
| --- | --- | --- |
| 图像类请求识别率 | 0（无图像意图） | ≥ 95% |
| 提示词结构完备率（8 段必有项） | 0 | ≥ 95% |
| 人工盲评均分（5 分制，5 维） | 2.6（原始一句话） | ≥ 4.0，且较基线 +0.8 |
| 负面约束覆盖率 | 0 | 100%（默认给基础负面词） |
| 安全红线拦截率 | 不适用 | 100% |
| 图像提示词 P95 耗时 | — | ≤ 30 ms（500 字输入） |
| 文本链路回归 | 192 用例全绿 | 保持全绿，新增用例 ≥ 30 |

### 1.2 范围内

1. 新增图像意图（`image`）与图像专用模板、成品骨架。
2. 图像提示词的结构规范与渲染器适配（双语结构，中文输入产中文提示词）。
3. 视觉维度词表：风格/流派、光线、镜头与焦段、构图、材质、画质与负面词。
4. 图像专用评分维度与安全过滤。
5. `/v1/meta` 暴露视觉维度清单；组件 chips 展示风格/构图/比例。
6. 图像语料库、自动断言、人工盲评流程、扩词基准。

### 1.3 范围外（本期不做）

- 不调用任何绘图模型、不生成图片；只产出提示词文本。
- 不做图生图、局部重绘、ControlNet 参数、种子/采样器调参。
- 不引入机器翻译：中文输入产中文提示词，英文输入产英文提示词（中译英列为 v2 评估项）。
- 不内置具体平台账号/API Key；平台方言只做**语法适配预设**。
- 不做批量生成、任务队列、历史图库。

### 1.4 兼容性约束（沿用现有工程纪律）

- 版本号单一来源 `engine.__version__`，发版时组件 `VERSION` 同步（现有用例守护）。
- 组件体积 ≤ 44 KB（当前余量 5,278 B），词表放服务端，前端只加展示。
- `/v1/meta` 负载 ≤ 12 KB（当前 6.7 KB），视觉清单按需分组。
- 词表变更必须过 `tools/expansion_bench.py` 门槛；测试走 `tests/run.py --strict`，跳过即失败。

## 2. 现有提示词模板的不足与优化方向

现有引擎是**文本提示词**流水线：`analyzer → templates → renderer → scorer`，模板固定 8 段（角色/目标/背景/步骤/约束/输出契约/自检/待确认），评分 5 维（清晰度/具体性/结构性/约束完备/可验证性）。直接套用到图像场景会失效：

| # | 不足 | 具体表现 | 优化方向 |
| --- | --- | --- | --- |
| 1 | 无图像意图 | 12 个意图里没有 `image`，「画一只赛博朋克猫」会落到 `general/writing` | 新增 `image` 意图与触发词（画/绘制/插画/海报/主图/头像/分镜/概念图/logo 草图…），并处理与 `writing`、`product`、`media` 的边界 |
| 2 | 结构不适配 | 「角色/目标/步骤」是给对话模型的指令结构；绘图模型需要视觉描述，且对「步骤」无感 | 定义图像 8 段：主体与动作 / 场景与环境 / 构图与视角 / 光线与氛围 / 风格与媒介 / 材质与细节 / 技术参数 / 负面约束 |
| 3 | 无视觉词表 | 现有词表是行业领域、投放渠道、语气；没有风格、镜头、光线、材质、画质、负面词 | 新建 6 类视觉词表，每类 40–80 词条，含中文别名与英文写法，并建立「领域 × 风格」合理性映射 |
| 4 | 无负向约束 | 文本模板只要求「不得编造」，没有图像负面词概念 | 默认注入基础负面 6 类（低质量/模糊/多余肢体/文字水印/畸变/过曝），并按场景追加 |
| 5 | 评分维度错位 | 用「结构性/可验证性」评图，会把堆砌形容词判为高分 | 图像场景切换维度：主体明确性/视觉具体性/构图完整/风格一致/技术合规与安全 |
| 6 | 平台差异未处理 | Midjourney 要 `--ar 16:9 --v 6`，SD 要权重语法与独立 negative 字段，DALL·E 3 偏好自然语言 | 增加「平台方言层」预设（MJ / SDXL / Flux / DALL·E 3），结构不变、渲染尾部差异 |
| 7 | 缺比例/分辨率意图 | 用户说「横版海报」「9:16 竖屏」时文本模板不识别 | 新增比例与用途抽取（16:9 / 9:16 / 1:1 / A4 海报 / 电商主图 / 头像），映射到 `--ar` 或描述句 |
| 8 | 无安全与版权边界 | 可能产出真人可识别肖像、未成年人敏感、在世艺术家署名、商标复刻 | 红线词表 + 改写/阻断策略 + 审计记录（本地，不联网） |
| 9 | 无图像评估集 | bench 语料全是文本领域/渠道/语气样本 | 新建 120 条图像语料（6 场景 × 4 风格 × 5 难度），纳入基准与 CI |

**优化原则**：结构先行、词表后补、评分独立、安全兜底；不改文本链路的模板与评分，图像能力通过 `intent=image` 分支隔离，确保文本零回归。

## 3. 分阶段规划

总周期 **6 周**（含 3 天缓冲）。阶段 2 与阶段 3 后 1 周可并行。

### 阶段 1：需求分析与场景定义（第 1 周）

**工作内容**
1. 采集 6 类高频场景：营销配图、电商主图、插画/封面、头像/人设、海报/展板、概念设计/分镜。
2. 确定首批平台目标与语法差异：Midjourney v6、SDXL、Flux、DALL·E 3。
3. 输出术语表（主体/构图/景别/光线/风格/材质/画质/负面）与安全红线清单。
4. 明确与现有意图的冲突边界（`writing`、`product`、`media`、`marketing`）。

**交付物**
- 《文生图场景与需求矩阵》（场景 × 平台 × 典型输入 × 期望输出）
- 《视觉术语表 v0.1》（8 类，每类 ≥20 条初稿）
- 《安全红线与处置策略》（拦截/改写/提示三类处置）
- 《意图边界判定表》（含 30 条易混样本及期望归属）

**验收标准**
- 场景矩阵覆盖 6 类场景，每类 ≥10 条真实输入；
- ~~30 条易混样本人工标注一致率 ≥90%（2 人独立标注）~~ → **豁免**（§9.6 E1：单源标注不产生一致率，
  改由「现状/目标双列 + 用例锁定」保障）；
- ~~红线清单经产品与法务确认~~ → **法务环节豁免**（§9.6 E2），产品确认由项目负责人承担；
  7 类覆盖现状：5 类有代码路径（真人肖像/暴力血腥/色情裸露/仇恨符号/商标+版权角色），
  **未成年人保护、在世艺术家署名仍为已知缺口**。

### 阶段 2：提示词结构设计（第 2–3 周，1.5 周）

**工作内容**
1. 定义图像提示词 8 段结构与必填/选填规则：主体、场景、构图、光线、风格、材质、技术、负面。
2. 设计中间表示（`Analysis` 扩展字段 + 渲染顺序），保证「同一输入输出稳定、可复现」。
3. 定义长度预算：中文 120–320 字，硬上限 900 字（可配）；英文 40–120 words。
4. 设计平台方言层：结构一致，尾部按平台追加（MJ 参数、SD 权重与 negative 字段、Flux 自然语言、DALL·E 3 纯描述）。
5. 与现有 API 对齐：`intent=image` 复用 `/v1/enhance` 与 SSE，`mode` 沿用 light/struct/deep/concise。

**交付物**
- 《图像提示词结构规范 v1.0》（含 8 段定义、顺序、必填规则、长度预算）
- 《平台方言映射表》（4 平台 × 语法示例 × 禁忌）
- 20 条端到端样例（6 场景全覆盖，含「一句话 → 成稿」对照）
- 接口契约增量说明（`analysis` 新增字段、`/v1/meta` 新增清单）

**验收标准**
- 20 条样例结构完备率 100%（8 段必有项齐全），人工可读性评分 ≥4/5（~~3 人盲评~~ → 单人盲评 + 锚点校准，见 §9 门槛修订 R3）；
- 长度合规率 100%，超限自动裁剪且不丢主体与风格；
- 4 平台语法抽检全部可被对应平台解析（MJ/SD 用语法校验脚本，Flux/DALL·E 3 人工确认）；
- 文本链路的 8 段结构与既有用例不受影响（全量 192 用例保持绿）。

### 阶段 3：关键词与风格维度扩充（第 3–5 周，2 周）

**工作内容**
1. 建 6 类视觉词表：风格/流派、光线、镜头与焦段、构图与视角、材质与细节、画质与负面。
2. 每类 40–80 词条，附中文别名、英文写法、适用场景权重；同义词去重，最长匹配优先。
3. 建立「领域 × 风格」合理性映射（如金融→简洁商务、游戏→概念设定、文旅→纪实/胶片），越界组合降权并提示。
4. 扩展 `/v1/meta`：`image_styles`、`image_lighting`、`image_composition`、`image_ratios`，按分组懒加载控制体积。
5. 建立扩词基准：旧词表快照 vs 当前词表，逐条对比召回。

**交付物**
- 6 类词表 v1.0（≥300 词条，含别名与英文）
- 《领域 × 风格映射表》与越界降权规则
- `image_*` 元数据清单与体积报告
- 扩词基准报告（新增语料 60 条：风格/镜头/光线各 20 条）

**验收标准**
- 风格、镜头、光线三类召回率 ≥90%（基准语料），且不低于旧词表快照（不退化硬门槛）；
- 领域 × 风格合理性抽样 100 条，判定合理率 ≥85%（2026-11-20 实测 **100%（100/100 可测，词表外 0）**，**已通过**：
  T1 灰区、T2 跨维度禁配、T3 维度归位依次落地，词表外仅剩 `概念设定`，归因见
  [`image-prompt/DOMAIN-STYLE-MAP-v0.1.md`](image-prompt/DOMAIN-STYLE-MAP-v0.1.md) §4.1）；
- 词表冲突/歧义（一词语义跨类）≤3%，同名不同义必须显式消歧；
- `/v1/meta` 负载 ≤12 KB，图像相关字段 ≤5 KB；
- 安全性：负面词表覆盖 6 类基础问题，重复/近义词去重率 100%。

## 5. 效果评估与持续优化机制

### 5.1 三层评估

| 层级 | 手段 | 频率 | 判定 |
| --- | --- | --- | --- |
| 自动断言 | 结构完备、负面词、长度、语法、禁用词 | 每次提交（CI） | 全绿才可合入 |
| 人工盲评 | 5 维 5 分制，单人 + 锚点校准，A/B 随机顺序（原 3 人独立 → §9 R3） | 每周抽样 ≥30 条 | 均分 ≥4.0（一致性仅在多人复评时计算） |
| 线上信号 | 复制率、重试率、复制后编辑距离、显式评分 | 持续 | 复制率 ≥60%，好评 ≥70% |

### 5.2 指标定义

- **结构完备率**：8 段中必填项齐全的样本占比。
- **主体忠实度**：提示词主体与用户原意一致（是否替换/丢失核心对象）。
- **视觉具体性**：是否给出可执行的构图/光线/风格，而非形容词堆砌。
- **风格一致性**：风格词与场景、领域不冲突（如「水墨风 + 赛博朋克」需显式标注为混搭）。
- **技术合规**：比例、平台语法、长度符合目标平台要求。
- **安全性**：红线命中拦截率、误拦率。

### 5.3 持续优化闭环

1. **采集**：线上失败样本（低评分、重试、复制后大改）进入本地样本池，脱敏后归档。
2. **归因**：四分类——词表缺失 / 结构缺失 / 平台方言 / 安全边界。
3. **改动**：补词、调结构权重、加平台映射、加红线；每次改动附「预期影响」与回归范围。
4. **回归**：跑 `tests/run.py --strict` + 扩词基准；词表变更必须「不退化 + 目标维度提升」。
5. **发布**：双周一个小版本（1.2.x），版本号单一来源，变更写入发布说明。
6. **复盘**：每两周看一次指标趋势，连续两周无提升则停止扩词，转向结构或评估方法改进。

### 5.4 质量闸门（Gate）

合入前必须同时满足：

- 全量用例通过（含新增图像用例），`--strict` 无跳过；
- 扩词基准：旧词表召回不下降，目标维度 ≥90%；
- 安全：红线样本 100% 拦截，无误拦（误拦 ≤2%）；
- 体积：组件 ≤44 KB、`/v1/meta` ≤12 KB；
- 性能：500 字输入 P95 ≤30 ms；
- 文档：结构规范、词表说明、接口字段与代码同批更新。

### 5.5 回滚与降级

- 能力开关：`--enable-image` 关闭后，图像请求回落到原文本增强行为；
- 词表/模板带版本号，异常时可切回上一版快照（保留 2 个版本）；
- 平台方言独立配置，单平台语法出错可只关闭该预设，不影响其余平台。

### 9.2 R3 为什么可以降为单人（理由写全）

1. **人力假设本来就是 1 人**：本文档 §4 的人力假设是「规则/后端 1 人、前端 0.5 人、测试 1 人、产品 0.5 人」，没有任何一位专职评审。原门槛写了 3 人，属于计划期的一厢情愿。
2. **凑不齐时硬凑更糟**：同一人扮演 3 个角色分开打分，得到的一致性系数（Krippendorff α / Fleiss κ）会虚高，反而把「没有分歧」当成结论。
3. **这个门槛实际要判的是方向，不是精度**：盲评的唯一用途是「系统输出 vs 原话」的 A/B 比较。§4.1 的实测差值是 +2.47 / +3.37 / +3.10 / +2.37 / +1.67，偏好率 100%——这个量级的差异不需要 3 人一致性来确认方向。
4. **有更硬的替代指标**：结构完备率、长度合规率、平台语法合法率、冗余三信号（跨段重复 / 壳词残留 / 长片段回声）都是机器可复现的客观项，已全部进断言；主观分只承担「好看不好看」这一项。

### 9.3 补偿控制（单人口径下必须做的 4 件事）

1. **先看锚点再打分**：3 条样板（4 分 / 3 分 / 5 分）内嵌在盲评页顶部，避免不同批次基线漂移。
2. **保留 10–20% 未改动条目作对照**：§4.4 的教训——对照组涨了 +3.00、已改组只涨 +2.12，说明「复评漂移」是真实存在的，没有对照组就无法把提升归因于改动。
3. **报告必须写明「单一评审者」**：结论强度上限是「内部可用」，不等于外部可用；任何小于 0.5 分的维度差异不作定论。
4. **偏差方向留档**：评审者知晓设计意图，存在期望偏差，因此**只采信「系统组 vs 原话组」这类同批次相对比较**，不采信跨批次绝对值。

### 9.4 恢复多人评审的触发条件（满足任一即回退到 3 人）

1. 对外发布、客户验收或对外披露效果数据；
2. 需要判定「平台间差异」「难度档差异」这类小于 0.5 分的结论；
3. 任一维度标准差 > 0.8，或出现天花板效应（零方差）；
4. 修订后的单人口径与历史多人数据出现方向性冲突。

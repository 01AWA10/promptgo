# 反馈闭环与双周复盘机制 v1.0

> 阶段 5 交付物 · 2026-11-17 · 配套脚本 `tools/feedback_report.py`，接入方式见 [`USAGE-v1.0.md`](USAGE-v1.0.md) §5

## 1. 一句话

灰度期不靠「感觉还行」判断上线：**复制率 + 好评率 + 重试率**三个数看方向，**失败样本池**看原因，
每两周用同一张看板、同一套归因分类过一遍，决定「继续放量 / 修一轮 / 关开关」。

## 2. 指标口径（先定口径，再谈数字）

| 指标 | 定义 | 门槛 | 为什么这样算 |
| --- | --- | --- | --- |
| 复制率 | `copy / enhance` | ≥60% | 分母是「出了结果」，不是「打开了页面」；复制是最强的采纳信号 |
| 重试率 | `retry / enhance` | 观察项，>20% 触发排查 | 不点「没用」但连点重试，是沉默的不满 |
| 好评率 | `有用 /（有用 + 没用）` | ≥70%，且样本 ≥50 | 不表态不算差评；样本不足时只当趋势，不当结论 |
| 归因完成率 | 已标注失败样本 / 失败样本总数 | 100% | 「知道哪里坏了」比「坏了多少」更重要 |

失败样本 = **「没用」票 + 重试请求**，不去重（同一需求反复重试本身就是信号）。

## 3. 归因四分类（唯一分类法，不许自创）

分类名沿用计划 §3 阶段 5 的四个词（不另起新名，避免台账与验收口径打架）：

| 分类 | 判定依据 | 典型修法 |
| --- | --- | --- |
| 词表缺失 | 图像链路成立，但某维度命中为空或命中错（如风格槽没东西可填） | 补词条 / 补别名 / 调场景权重 |
| 结构缺失 | 该走图像链路却没走，或 8 段有明显缺项 | 补意图关键词、补场景默认段 |
| 平台语法 | 平台参数、负面词写法或语言不符合目标平台 | 改 `render` 的方言拼装 |
| 安全问题 | 命中红线被拦、或软红线改写后语义跑偏 | 调 `SAFETY_*` 词表与改写词 |

`tools/feedback_report.py` 会先给一个**归因候选**（离线复跑该条输入 + 规则判定），
但候选只是提效，**必须人工确认后写入台账**才算完成，不确认按「未归因」计。

## 4. 台账与样本池

```
docs/image-prompt/feedback/attribution.json   # 人工归因台账：{"<文本指纹>": "词表缺失"}  ← 四类之一
docs/image-prompt/feedback/failures-<日期>.md  # 导出件：给人读，含原文与候选
```

```bash
python tools/feedback_report.py --export docs/image-prompt/feedback/failures-2026-12-01.md
# 逐条确认后把 {"指纹": "分类"} 填进 attribution.json，看板自动算完成率
```

指纹 = 原文 sha1 前 12 位，改一个标点就会变——这是故意的：**同一句话改过就是新样本**，
避免「改完还挂旧账」。

## 5. 双周复盘（每两周一次，30 分钟）

**会前**（10 分钟，脚本跑完即出图）：

```bash
python tools/feedback_report.py
python tools/feedback_report.py --export docs/image-prompt/feedback/failures-$(date +%F).md
```

**会上**（15 分钟，按顺序过，不跳步）：

1. 三个数对比上期：复制率、好评率、重试率。只看方向，不做小数点级别的归因。
2. 新增失败样本逐条过归因，当场定分类（定不了就标「待观察」，但下次必须定）。
3. 按分类聚合，选出本期**投入产出最高的一类**（例：词表缺失 12 条 → 补 5 个词）。
4. 决定灰度动作：继续 / 放量 / 暂停（见 §6）。

**会后**（5 分钟）：把结论追加进 [`GRAY-REPORT-v0.1.md`](GRAY-REPORT-v0.1.md) §4 的期次表，
写明「改了什么、预期哪个指标动、下期怎么验」。

## 6. 灰度动作的触发规则

| 触发条件 | 动作 |
| --- | --- |
| 出现 P0/P1（红线漏放、崩溃、越权） | 立即 `--enable-image off` 回滚，事后复盘 |
| 好评率连续两期 <70% 且样本 ≥50 | 暂停放量，先修失败样本池里最高频的一类 |
| 重试率 >20% | 按「结构缺失」方向查，通常是意图或某维度整体没填 |
| 复制率 <60% | 先看是否平台方言选错（用户要 MJ 却给了通用），再看长度是否过长 |
| 三个数都在门槛内且无 P0/P1 | 放量（内测人数 ×2） |

## 7. 复盘纪律（三条约定的原因）

1. **口径不许改**：想改口径先写进本文件并注明生效期次，否则跨期数字不可比。
2. **候选不算归因**：脚本给的是候选，人工确认才入库——否则「完成率 100%」是假的。
3. **失败样本不外传**：日志只在本机，导出件只放仓库 `docs/image-prompt/feedback/`，
   不含用户身份信息（服务端不记 IP）。

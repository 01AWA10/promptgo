## 1. 判定等级与系数

| 等级 | 含义 | 权重系数 | 输出处置 |
| --- | --- | --- | --- |
| 推荐 | 该领域的主流视觉语言 | 1.0 | 用户未指定风格时作为默认值填入 S5 |
| 中性 | 不冲突、也不加分 | 0.9 | 用户显式点名时保留 |
| 灰区 | 需额外条件才成立（如「复古」需限定年代） | 0.8 | 保留但追加限定词，并在 `analysis.image.warnings` 记一条 |
| 禁配 | 与领域调性或合规冲突 | 0.5 | 风格维替换为最近的推荐项，其它维度（光线/镜头/材质/负面）直接移除；两种情况都提示 |

**叠加规则**：最终权重 = 词表场景权重（术语表 §3）× 领域系数，封顶 1.1。系数 <0.7 的词直接不进候选。

## 3. 判定算法（伪代码）

```text
def pick_style(domain, text, user_style_hits, scene):
    table = DOMAIN_STYLE[domain]                      # 上表四列
    for term in banned_hits(text, domain):            # 禁配：按输入命中，含跨维度词
        purge(term)                                   # 从所有命中维度剔除
        if term.dim == "style":
            fill("style", first(table["推荐"]))        # 风格维补领域首选
        warn("style_conflict", term)                  # 复用替换/移除两种文案
    cands = []
    for term in STYLE_TERMS:                          # 术语表 T5，44 条
        base = scene_weight(term, scene)              # 术语表 §3：1.0 / 0.9 / 0.7
        tier = tier_of(table, term)                   # 推荐/中性/灰区/禁配
        coef = {"推荐": 1.0, "中性": 0.9, "灰区": 0.8, "禁配": 0.5}[tier]
        w = min(base * coef + explicit_bonus(term, user_style_hits), 1.1)
        if w >= 0.7:
            cands.append((term, w, tier))
    if not user_style_hits:                           # 用户没说风格
        top = first(table["推荐"])                    # 取推荐首位
        return top, ["style_default"]
    return top2(cands), [f"style_conflict:{t}" for t, _, t_ in cands if t_ == "灰区"]
```

**禁配判定（2026-11-17 改）**：不再只看「匹配到的风格词是否在禁配列」，而是拿**输入**去比禁配词表——
命中即把该词从所有命中的维度里剔除（跨维度也剔），风格维再补领域首选，并记一条 `style_conflict`。
理由：禁配列里混着光线（`低调`）、镜头（`鱼眼镜头`）、材质（`做旧`）、负面（`恐怖元素`）等非风格维词，
只比对 style 槽位等于放行，实测 10 条禁配样本因此照进正文（见 §4.1）。
文档写法与引擎词的对应（`卡通`→`低多边形`、`暗调低调`→`低调`）由 `visual.ban_forms()` 归一。

**替换文案**（禁配命中时）：
- 风格维：`「{user_style}」与 {domain_label} 场景的视觉调性冲突，已替换为「{replacement}」；如需保留原风格请明确说明。`
- 其它维度（光线/镜头/材质/负面）：`「{term}」与 {domain_label} 场景的视觉调性冲突，已从提示词中移除；如需保留请明确说明。`

**追问上限**：风格冲突不单独追问，只做替换 + 提示（规范 §6：一次最多问 2 个，风格歧义优先让位于主体缺失）。

## 4. 抽样校验口径

阶段 3 验收要求「领域 × 风格合理性抽样 100 条，人工判定合理率 ≥85%」。抽样构造：

- 每领域取 4–5 组（推荐 ×2、中性 ×1、灰区 ×1、禁配 ×1），22 领域共 100 条；
- 判定标准：该组合放进提示词后，是否会让懂行的人觉得「不对劲」——有 → 不合理；
- 灰区条目额外检查「限定词是否自动补齐」，缺席即判不合理。

**判定不看表、只看输出**：样本从本文件表格解析（改表即改样本），判定则跑真实引擎——
`做一张{领域词}的宣传图，风格要{术语}` → 看 `analysis.image.segments.style` 与 `warnings`。
理由：「该组合合不合理」最终由用户拿到的提示词决定，而不是由表写得漂不漂亮决定。

#### 禁配实现（2026-11-17）

| 环节 | 改前 | 改后 |
| --- | --- | --- |
| 表 | 引擎 `DOMAIN_STYLE` 禁配列只收风格维词，且与 §2 不一致（`energy` 缺 `低多边形`、`ecommerce` 多 `拼贴`） | 禁配列与 §2 **逐字一致**，由 `tests/test_bench_tools.py::DomainBanTestCase` 守着 |
| 判据 | `matched["style"] in banned`（只看风格槽位） | `visual.banned_hits(text, domain)`：拿输入比禁配词表，命中即处理 |
| 处置 | 只替换 style | 从**所有命中维度**剔除（style 补领域首选；lens 回落到场景默认机位；lighting/texture 回落到场景默认），并记 `style_conflict` |

#### 灰区实现（2026-11-17）

灰区不是「一律补字」：本表第 4 列的括号有两种语义，硬塞会让句子变形，因此分两类落库
（`visual.DOMAIN_STYLE_GRAY`，`q` = 需限定，`c` = 适用条件）：

| 类型 | 例 | 引擎行为 | 用户看到 |
| --- | --- | --- | --- |
| `q` 需限定 | `energy` × 电影感（需「克制调色」） | 把「克制调色」追加进 S5，并记 `style_gray` | 「电影感…，克制调色」+ 提示「在新能源场景需限定，已补充」 |
| `c` 适用条件 | `marketing` × 像素艺术（仅年轻向活动） | 保留风格，只记 `style_gray` | 正文不变 + 提示「仅适用于：仅年轻向活动」 |

判据：塞进正文会读成怪句的（「像素艺术，仅年轻向活动」）归 `c`；不塞就自相矛盾的（「电影感」不限限定＝高对比大片）归 `q`。
引擎表与本表 §2 逐字一致，由 `tests/test_bench_tools.py::GrayTierTestCase` 守着，改表不改代码会直接红。

#### 维度归位（2026-11-18，T3）

本表四列混装了其它维度：`建筑外观`/`风光`/`食物特写` 是主体维，`干净背景`/`胶片颗粒` 是画质维，
`影棚柔光`/`暖调自然光`/`冷蓝`/`暗调低调` 是光线维，`微距` 是镜头维。引擎此前只有 6 个渲染槽位，
这些词要么被用户主体覆盖（主体维）、要么根本没槽位（画质维），表现为「点名了却没落地」。修法分两层：

| 层 | 改动 | 效果 |
| --- | --- | --- |
| 词表（同义） | `_ALIAS_EXTRA` 给真实维度词补同义：`生活方式摄影`→`纪实摄影`、`古典油画`→`油画`、`复古胶片`→`胶片摄影`、`微距`→`微距镜头`、`白底无缝背景`→`无缝背景`、`影棚柔光`→`影棚布光`、`暖调自然光`→`自然光`、`冷蓝`→`蓝调时刻`、`简洁商务摄影`→`商业产品摄影`、`暗调低调`→`低调` | 词表外 13 条 → **1 条**；`TERM_COUNT` 仍 324（补的是别名，不是新词条） |
| 段落（归位） | 主体维命中与用户主体并存时挂到 S2（`房产` + `建筑外观`）；画质维命中并入 S7（`16:9 画幅，干净背景，高分辨率…`，`_dedupe` 防重复） | 主体维不再被覆盖丢弃，画质维不再无处可去 |
| 匹配（最长） | `match_terms()` 的最长匹配从「主词长度」改为「**命中写法长度**」 | `复古胶片`（`胶片摄影` 别名）不再被更短的 `复古` 抢走 |
| 灰区（落点） | 灰区 holder 按 `TERM_CANON` 找主词，且改在 S7 之后再判 | `暗调低调`→`低调`（光线段）、`胶片颗粒`（技术段）都能被找到并留痕 |

**词表外 1 条**：`概念设定`（concept art）。它不是任何现有词的同义，需新增词条——属词表扩容，
会动 `TERM_COUNT`、`VISUAL-TERMS-v1.0` 的分维度计数与 meta 体积基线，留给下一版词表（v1.2）处理。

**五轮数字的变化都要能解释（45% → 61% → 80% → 92% → 100%）**：

1. **首轮 45%（45/100）→ 61%（53/87）**，源于两处，都不是「把分数调高」：
   - 修掉一个真 bug：`match_terms()` 拿词表主词直接比对**已 lower 的文本**，导致含大写拉丁字母的主词
     （`3D 渲染`、`2.5D 插画`）永久不可命中。改在 lower 后的文本上比之后，这两条从「不可测」变成「可测且合理」，
     并顺带修掉「用户点名 3D 渲染却得到写实摄影」的缺陷；
   - 分母变小：13 条文档术语不在 324 词表内（本表把光线/构图/材质/背景词写进了「风格」列），
     记为「词表外」移出分母。这一项不提高合理率，只是不拿文档自身的分类错误给引擎扣分。
2. **61% → 80%（70/87）**：灰区梯队落地（T1，上节），灰区由 0/18 升到 17/18，其余分档不变。
3. **80% → 92%（80/87）**：跨维度禁配落地（T2，上节），禁配由 12/22 升到 22/22，其余分档不变。
4. **92% → 100%（99/99）**：维度归位落位（T3，上节）。这一步**分子分母同时变大**——12 条词表外样本
   被补成同义计入分母（87 → 99），同时 7 条不合理全部转正（80 → 99）。不是把难样本剔掉，
   而是把「以前算不进去的」变成「必须过且已过」。

**结论**：文档的四级判定已全部有代码对应，抽样口径下**没有不合理样本**（99/99）。
这是「承接率」，不等于「画出来好看」——它只证明用户点名的词都落了地、灰区补了限定、禁配被拦；
主观质量仍看阶段 4 的盲评（§4.2）。

## 5. 与「混搭」需求的关系

用户明确要混搭（如「国潮 + 赛博朋克」）时，禁配规则让位于用户意图，但必须做到：

1. 两个风格都保留，顺序按「先主体后氛围」；
2. 追加「风格融合过渡自然」，并删除「风格混杂」负面词（否则自相矛盾）；
3. 在 `analysis.image.warnings` 记 `style_mix`，供阶段 4 盲评单独归因。
